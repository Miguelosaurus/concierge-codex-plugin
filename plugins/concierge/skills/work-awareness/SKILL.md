---
name: work-awareness
description: Use for explicit Work Awareness settings/disposition requests, a meaningful changed checkpoint in an eligible native root, or orientation from a verified-owner phone briefing.
---

Work Awareness is optional, incomplete orientation into native Codex work. A dated summary is a clue, never authoritative current status; absence proves nothing about other work. Native Codex owns history. Owner-only context never grants effect or return-call authority.

Choose only the applicable branch and reuse guidance already loaded in the current context:

- **Publish/retire:** an eligible root has a meaningful changed checkpoint and the setting is enabled or unknown → [publishing.md](references/publishing.md).
- **Settings/disposition:** the owner explicitly requests enable/disable/dismiss, or an exact item was actually discussed → [settings.md](references/settings.md).
- **Phone retrieval:** a verified owner asks about work or receives a relevant briefing → [phone-retrieval.md](references/phone-retrieval.md).

Known-disabled, child, trivial and unchanged work skips optional publishing silently. Stop alone is not a checkpoint. Awareness never blocks Stop or creates continuation; unfinished native work and mandatory close-loop obligations still follow `close-the-loop`.
